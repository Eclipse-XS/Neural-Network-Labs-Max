## 1. Загальний огляд проєкту

Репозиторій містить комплекс навчально-дослідницьких реалізацій для курсу «Технології та системи нейронних мереж» (лабораторні роботи 1–7). Дослідження охоплюють фундаментальні аспекти сучасного глибокого навчання: реалізацію трансформерних архітектур на чистому PyTorch, високоефективний сервінг LLM, векторні бази даних та RAG-системи, дифузійні моделі генерації зображень, мультимодальний зір (Vision-Language) та автономні агенти з плануванням дій.

Лабораторні роботи 3–7 реалізовані відповідно до **Варіанту 2** навчального плану. Усі матеріали організовані за принципом відтворюваності: дослідження супроводжуються виконуваними Jupyter-ноутбуками, зафіксованими артефактами інференсу, детальними звітами та наборами модульних тестів.

## 4. Налаштування та запуск

Через специфіку апаратних вимог різні лабораторні роботи потребують різних компонентів оточення:

| Лабораторна робота | Середовище виконання | Апаратні вимоги | Необхідні сервіси та ваги |
|---|---|---|---|
| **ЛР 1** | Windows / Linux / macOS (Python 3.11+) | CPU або CUDA GPU (до 4 ГБ VRAM) | Локальні файли датасетів (завантажуються автоматично) |
| **ЛР 2** | Linux або Windows із WSL2 | NVIDIA GPU (від 4 ГБ VRAM для AWQ) | vLLM сервер, ваги `Qwen/Qwen2.5-1.5B-Instruct-AWQ` |
| **ЛР 3** | Windows / Linux / macOS | CPU або GPU | Локальний сервер Ollama (`qwen3:4b-instruct`) або vLLM |
| **ЛР 4** | Windows / Linux | NVIDIA GPU з підтримкою CUDA (від 4 ГБ VRAM) | Ваги `runwayml/stable-diffusion-v1-5` (завантажуються через Hugging Face) |
| **ЛР 5** | Windows / Linux / macOS | GPU (для режиму `LIVE`) або CPU (для режиму `ANALYSIS_ONLY`) | Ваги `llava-hf/llava-interleave-qwen-0.5b-hf` (у режимі LIVE) |
| **ЛР 6** | Windows / Linux / macOS | CPU або GPU | Локальний OpenAI-сумісний ендпоінт Ollama (`qwen3:4b-instruct`) |
| **ЛР 7** | Windows / Linux | NVIDIA GPU (від 4 ГБ VRAM для повного циклу) + CPU | Ollama, ваги LLaVA та Stable Diffusion 1.5 |

### Базове встановлення залежностей

```bash
# Створення та активація віртуального середовища
python -m venv .venv
# Windows:
.\.venv\Scripts\activate
# Linux/macOS:
source .venv/bin/activate

# Встановлення PyTorch з підтримкою CPU або CUDA (залежно від платформи):
pip install torch --index-url https://download.pytorch.org/whl/cpu

# Встановлення базових залежностей для перевірки та блокнотів:
pip install pytest nbformat nbclient pandas matplotlib pillow streamlit openai
```

## 5. Тестування та відтворюваність

Тестовий набір репозиторію розділено на три функціональні категорії:

1. **CI-сумісні тести (109 тестів):**
   - Перевіряють валідність JSON-структури всіх 19 Jupyter-ноутбуків (`nbformat.validate`).
   - Тестують математичні алгоритми, маски, токенізацію, валідацію вхідних параметрів CLI, роботу з метаданими, логіку пісочниці та схеми реєстрів без потреби у важких GPU-обчисленнях.
   - Автоматично виконуються в GitHub Actions на Ubuntu Runner:
     ```bash
     pytest lab1/tests lab2_vllm/tests lab4_img2img/tests lab5_multimodal_captioning/tests lab6_llamaindex_agents/tests lab7_multimodal_studio/tests lab3_chroma_rag/tests/test_lab03_markdown_regression.py -v
     ```

2. **Локальні інтеграційні тести:**
   - Покривають роботу з персистентною векторною базою ChromaDB (`lab3_chroma_rag/tests/test_lab03.py`), повну перевірку SQLite галереї та взаємодію локальних модулів.
   - Виконуються на робочій станції за наявності встановлених бібліотек C++ векторного бекенду.

3. **Реальні експерименти інференсу на GPU:**
   - Генерація дифузійних зображень, інференс зорових моделей LLaVA та виклики локального сервера vLLM/Ollama виконуються через інтерактивні клітинки Jupyter-блокнотів або CLI-скрипти за наявності відповідного апаратного забезпечення.
   - Усі згенеровані результати зафіксовані в директоріях `outputs/` відповідних лабораторних робіт.

> [!NOTE]
> Автоматичний пайплайн CI не виконує важкий інференс нейромереж на GPU, а фокусується на валідації архітектурних контрактів, цілісності збережених артефактів, схем блокнотів та логіки безпеки.

## 6. Короткі результати лабораторних досліджень

- **ЛР 1 (Transformers):** Реалізовано чистий PyTorch-енкодер для класифікації спаму Enron ($F_1 = 0.9668$) та причинний декодер для генерації тексту на базі WikiText-2 (кінцевий $\text{Perplexity} = 148.48$). Детальний звіт: [lab1/REPORT_DRAFT.md](./lab1/REPORT_DRAFT.md).
- **ЛР 2 (vLLM):** Налаштовано сервінг квантованої моделі `Qwen2.5-1.5B-Instruct-AWQ` у WSL2. Проведено параметричні експерименти з `temperature` та `max_tokens`; підтверджено коректне збереження історії діалогу. Деталі: [lab2_vllm/README.md](./lab2_vllm/README.md).
- **ЛР 3 (ChromaDB RAG):** Побудовано персистентну базу знань із 8 документів (55 чанків). Досліджено баланс релевантності та різноманітності алгоритму MMR (`fetch_k` $= 12$, $k=4$, $\lambda=0.5$) та генерацію відповідей із прив'язкою до вилученого контексту. Звіт: [lab3_chroma_rag/report/report.md](./lab3_chroma_rag/report/report.md).
- **ЛР 4 (Stable Diffusion Img2Img):** Проведено параметричний аналіз впливу коефіцієнта `strength` (0.3 / 0.6 / 0.9), сили спрямування CFG та кількості кроків денойзингу. Збережено 14 PNG-зображень (10 унікальних конфігурацій) та 13 файлів JSON-метаданих. Звіт: [lab4_img2img/report/report.md](./lab4_img2img/report/report.md).
- **ЛР 5 (LLaVA Captioning):** Досліджено генерацію описів 4 різнорідних сцен за допомогою моделі `LLaVA-Interleave-Qwen-0.5B` у FP16 на 4 ГБ VRAM. Зафіксовано залежність затримки від бюджету токенів та оцінено повноту опису об'єктів. Звіт: [lab5_multimodal_captioning/README.md](./lab5_multimodal_captioning/README.md).
- **ЛР 6 (LlamaIndex Agents):** Реалізовано інженерного агента з 4 спеціалізованими інструментами, контекстною пам'яттю `ChatMemoryBuffer` та обробкою подій виклику функцій. Оцінено 9 цільових сценаріїв взаємодії. Опис: [lab6_llamaindex_agents/README.md](./lab6_llamaindex_agents/README.md).
- **ЛР 7 (Multimodal Studio):** Створено інтегрований веб-додаток на базі Streamlit, що об'єднує функції LLaVA, Stable Diffusion 1.5, оркестрацію LlamaIndex та персистентну SQLite-галерею з валідацією шляхів пісочниці. Опис: [lab7_multimodal_studio/README.md](./lab7_multimodal_studio/README.md).

## 7. Технічні обмеження

1. **Апаратні обмеження відеопам'яті:** Робота локальних генеративних та мультимодальних моделей проводилася на мобільному GPU з 4 ГБ VRAM. Для запобігання помилкам Out-Of-Memory (OOM) обов'язковим є використання половинної точності (FP16), квантування (AWQ / 4-bit) та механізмів вивантаження вагів (`enable_model_cpu_offload`).
2. **Платформна залежність vLLM:** Фреймворк vLLM вимагає середовища Linux (або WSL2 на Windows).
3. **Обмеження контексту та локальних моделей:** Компактні моделі (0.5B–4B параметрів) чутливі до формулювання промпту; вибір інструментів агентом потребує суворого структурування функціональних сигнатур.
4. **Офлайн-режим перевірки:** Автоматизовані тести в CI використовують моковані або попередньо збережені артефакти для швидкої перевірки контрактів без підключення до фізичних GPU.
