## 1. Архітектурний огляд та концепція

Лабораторна робота присвячена побудові автономного інженерного агента-помічника (**MLOps Incident Copilot**), здатного в режимі реального часу моніторити стан промислової інфраструктури машинного навчання, виявляти деградацію сервісів, зіставляти телеметрію з цільовими угодами про рівень обслуговування (SLO) та витягувати регламентні інструкції з ліквідації аварій (incident runbooks).

Система реалізована за сучасною workflow-first архітектурою `LlamaIndex 0.14+` (`llama_index.core.agent.workflow.AgentWorkflow`) з підключенням локального OpenAI-сумісного сервера `Ollama` (`qwen3:4b-instruct`), що усуває залежність від хмарних API та гарантує повну конфіденційність інфраструктурних даних.

```
+-----------------------------------------------------------------------------------+
|                           LlamaIndex AgentWorkflow                                |
|                                                                                   |
|  [ User Prompt / Alert ] ---> [ ChatMemoryBuffer ] <---> [ OpenAILike LLM ]       |
|                                       |                          |                |
|                                       v                          v                |
|                           [ Event Streaming Handler ] <---+ Function Call         |
+---------------------------------------|-------------------------------------------+
                                        |
                 +----------------------+----------------------+
                 |                      |                      |
                 v                      v                      v
        [ query_model_registry ] [ consult_incident_runbook ] [ calculate_slo_margin ]
        (Structured JSON Store)     (Unstructured Runbook)    (Quantitative Math)
                 |                      |                      |
                 +----------------------+----------------------+
                                        |
                                        v
                       [ Synthesized Engineering Report ]
```

## 3. Спеціалізовані інструменти агента

1. **`query_model_registry(model_id: str)`**:
   - Отримує поточний статус, P50/P99 затримку, рівень доступності, частку помилок та цільовий SLO для заданої моделі з файлу `models_registry.json`.
2. **`list_degraded_models()`**:
   - Повертає список усіх моделей інфраструктури, що перебувають у неробочому або деградованому стані.
3. **`consult_incident_runbook(query: str)`**:
   - Здійснює лексичний пошук за ключовими словами (keyword lexical retrieval) розділів інцидентного регламенту у `mlops_runbook.txt` (протоколи прискореного кешування, скейлінг реплік, перезапуск worker-пулів з chunked prefill, rollback).
4. **`calculate_slo_margin(metric_value: float, slo_target: float, metric_type: str)`**:
   - Виконує точний чисельний розрахунок відхилення затримки або доступності від SLO, класифікуючи рівень загрози (`Critical`, `Warning`, `Nominal`).

## 4. Контекстна пам'ять та автономна оркестрація

- **Контекстна пам'ять (`ChatMemoryBuffer`)**:  
  Забезпечує безперервність сесії між репліками діалогу. Агент запам'ятовує об'єкт дослідження (наприклад, `recommender_ranker_v5`), дозволяючи користувачеві ставити уточнювальні запитання без повторного зазначення імені моделі.
- **Автономне планування (Multi-Step Tool Chaining)**:  
  Агент самостійно будує ланцюжок дій: виявлення моделі $\rightarrow$ розрахунок запасу SLO $\rightarrow$ запит до регламенту $\rightarrow$ формування інтегрованого звіту з командами ліквідації аварії.
- **Стійкість та безпека (Safety Refusal)**:  
  При отриманні деструктивних команд (наприклад, видалення реєстру моделей) агент чемно відхиляє запит, повідомляючи про обмеження повноважень.
