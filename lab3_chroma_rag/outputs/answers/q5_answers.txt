QUERY: What are the key architectural differences in memory footprint between Distributed Data Parallel (DDP) and Fully Sharded Data Parallel (FSDP)?
FILTER: None

============================================================
SIMILARITY RETRIEVER ANSWER:
============================================================
The key architectural difference in memory footprint between Distributed Data Parallel (DDP) and Fully Sharded Data Parallel (FSDP) lies in how model parameters, gradients, and optimizer states are distributed across GPU ranks.

- In **Distributed Data Parallel (DDP)**, model parameters and optimizer states are replicated across all GPU ranks. This results in a per-device VRAM footprint of $O(M)$, where $M$ is the total model size, because each rank holds a full copy of the model parameters and optimizer states [03_model_training.md | ID: 03_model_training_chunk_005].

- In **Fully Sharded Data Parallel (FSDP)**, model parameters, gradients, and optimizer states are partitioned (sharded) across ranks. This reduces the per-device VRAM footprint from $O(M)$ to $O(M / N)$, where $N$ is the number of GPU ranks, as only a fraction of the model state resides on each device [03_model_training.md | ID: 03_model_training_chunk_006].

Thus, FSDP significantly reduces memory overhead compared to DDP by eliminating redundant parameter copies and enabling on-demand gathering of parameters during computation.

The key architectural difference in memory footprint between Distributed Data Parallel (DDP) and Fully Sharded Data Parallel (FSDP) lies in how model parameters, gradients, and optimizer states are distributed across GPU ranks.

In DDP, model parameters and optimizer states are replicated across all GPU ranks, leading to a per-device VRAM footprint of $O(M)$, where $M$ is the total model size. This replication results in high memory usage, especially for large models, as each GPU holds a full copy of the model state.

In contrast, FSDP shards model parameters, gradients, and optimizer states across ranks, reducing the per-device VRAM footprint from $O(M)$ to $O(M / N)$, where $N$ is the number of GPU ranks. This is achieved by gathering parameters on-demand during forward and backward passes, minimizing the memory footprint per device [03_model_training.md].

Thus, FSDP significantly reduces memory overhead compared to DDP due to its sharding mechanism, making it more scalable for large models on multi-GPU systems.
